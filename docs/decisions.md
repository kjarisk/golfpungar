- 2026-05-17: Phase 23C RLS built — 3 migrations: 5 `private` helper functions (`is_admin`, `is_tournament_member`, `is_in_round_group`, `owns_player`, `round_has_status`; all `SECURITY DEFINER STABLE`, `EXECUTE` granted to `authenticated`), then 84 policies (one per action × 21 tables). The plan's `current_player_id()` helper was dropped — a user has one `players` row *per tournament*, so there is no single global player id; `owns_player(player_id)` covers every "is this me?" check instead. Policies fold admin in with `OR` (`is_admin() OR <player rule>`) so each table has exactly one permissive policy per action — avoids the `multiple_permissive_policies` advisor warning. All policies target `authenticated` only; `anon` is denied everywhere (the app is invite-only/login-required). Score-entry RLS is gated at round-group granularity (`is_in_round_group` + `round_has_status(...,'active')`); the finer "your group only" scoping stays a UI concern. Column-level limits (player can't edit own handicap; team member can only rename) are enforced by `BEFORE UPDATE` guard triggers on `players`/`teams`, since RLS gates rows not columns. `get_advisors` (security) returns zero findings.
